Memo 0.14.1 is released: https://github.com/openbohemians/memo/releases/tag/v0.14.1. It fixes bugs an independent review found, and the first one affects searches scoped with `sql_where`, which ipck uses with artistry.

**The bug (0.13.0 through 0.14.0):**
- Since 0.13.0, a text is embedded once however many sources share it.
- Search applied the filters (`sql_where`, `source_type`, the id filters, `like`, `match`) to embeddings, then returned every source with that text, including sources the filters exclude.
- Example: `sql_where: "c.source_type = ?"` with "public" also returned a "private" source that had the same text.
- 0.14.1 returns only chunks that pass the filters, on SQLite and Postgres. Your `sql_where` is evaluated against each result chunk (`c`) as documented.

**Behavior changes to check on your side:**
- An id filter that names no source now finds nothing. It used to be dropped, which widened the search to everything.
- `search` raises `ArgumentError` for filters it can't apply, instead of ignoring them: `source_id`, `pair_id` or `parent_id` without `source_type`, and `like` or `match` on a service opened with `store_text: false`.

**Also fixed:**
- Indexing a source again while its older text was still being embedded could leave the older text indexed for good.
- Deleting a source left its queued work, which could bring it back.
- Indexing a blank text left the old chunks searchable.

No schema or API changes, so `shards update memo` is all it takes. If copious, ipck or justice build against Memo's working tree, they already have these fixes.
